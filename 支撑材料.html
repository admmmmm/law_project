01_项目代码仓库与工程结构说明

一、代码仓库基本情况

本项目代码仓库采用前后端分离结构，围绕“案件材料接入—证据图谱构建—图谱支撑检索—智能分析—侦查画像—证据溯源”的业务链路组织。后端以 FastAPI 为核心，提供案件管理、材料导入、证据地图、智能分析、画像报告、法律知识库和检察分析技能包等接口；前端基于 Vue3 + Vite + TypeScript，实现案件导入、图谱展示、智能分析、画像生成和溯源查看等交互页面。系统同时包含脱敏演示数据、法律知识库、结构化样本数据、截图脚本和运行部署配置，能够支撑比赛演示和功能验证。

三、后端代码说明

后端主要位于 backend/app 下。api/v1/routes 负责提供 HTTP 接口，覆盖案件管理、材料导入、图谱查询、证据地图、智能分析、画像报告、法律知识和技能包等功能；services 是业务服务层，承担材料接入、分析、图谱、画像、规则包、法律知识等核心逻辑；adapters 负责算法与 HippoRAG 适配；schemas 定义前后端数据契约；storage 负责 SQLite JSON payload 持久化。

其中，支撑方案蓝图和核心功能的重点文件包括：

四、前端代码说明

前端主要位于 frontend/src 下。views 目录承载核心页面，包括案件导入与管理、案件证据地图、智能分析、侦查画像、法律知识库等；components 目录包含图谱组件、G6 图谱渲染组件和页面通用组件；api/backend.ts 负责封装后端接口调用；router.ts 负责页面路由。图谱展示主要由 Graph.vue 和 G6EvidenceGraph.vue 实现，智能分析页面由 Intelligence.vue 实现，画像页面由 Portrait.vue 实现。

五、数据库与状态存储说明

当前系统没有使用传统 ORM 模型，而是采用 SQLite 表保存 JSON payload，同时保留内存字典缓存。SQLite 用于保存案件、证据、原文、抽取结果、图谱、画像、分析会话、检索过程、文件母图和规则运行记录，是原型阶段的统一状态仓库。相关数据模型包括 cases、evidence、raw_contents、extractions、graphs、reports、portrait_facts、analysis_threads、analysis_messages、retrieval_sessions、retrieval_steps、document_mother_nodes、analysis_skill_registry、rule_pack_runs 等。

03_核心技术模块说明

一、证据接入与预处理模块

模块目标

该模块用于解决案件材料来源多、格式复杂、文本长、结构化记录数量大等问题。系统通过统一导入、解析、切片和编号，将原始卷宗、笔录、流水、通信等材料转化为后续可检索、可建图、可溯源的证据单元。

实现方式

系统提供文本导入、单文件导入、多文件导入和 ZIP 压缩包导入能力。材料进入系统后，先进行文件类型判断和内容解析，再对非结构化文本进行切句或切片，对结构化数据进行行级解析，并生成 evidence_id 保存入库。支持格式包括 .txt、.md、.csv、.xlsx、.json、.pdf、.docx，其中 .doc 暂不支持。

输出结果

模块输出包括证据文件元数据、原文内容、证据片段、结构化抽取结果和基础事实关系，为证据图谱构建和检索分析提供底座。

二、案件证据图谱构建模块

模块目标

该模块用于解决材料分散、事实要素隐藏、证据之间缺乏结构化关联的问题，将案件材料组织为“文件—片段—事实—关系”的案件证据图谱体系。

实现方式

系统通过 EvidenceMapService 和 EvidenceMapBuilder 构建证据地图，返回 documents、passages、triples、document_edges、passage_edges、containment_edges 等结构。文件层基于 EvidenceRecord 与 DocumentMotherNode 构建，片段层基于 ExtractionResult.passages 和原文切片构建，事实关系层基于 ExtractionResult.triples、HippoRAG OpenIE 合并图和本地抽取结果构建。三层图谱分别对应材料边界、证据定位和事实关系分析。

输出结果

形成文件层图谱、片段层图谱和事实关系层图谱。文件层回答“材料从哪里来”，片段层回答“证据在哪里”，事实关系层回答“事实如何关联”。这些图谱为后续关系扩展、智能分析和侦查画像提供结构化基础。

三、图谱支撑检索模块

模块目标

该模块用于解决普通检索只能找到相似文本、难以发现多跳关系和交叉线索的问题。系统通过图谱筛选、邻域扩展、多跳召回和子图交叉，把分散证据组织为可观察的局部证据网络。

实现方式

前端图谱页面由 Graph.vue 和 G6EvidenceGraph.vue 实现，系统支持文件层、片段层、事实关系层切换。图谱页中的核心邻域、邻域扩展、多跳召回和子图交叉，当前主要由前端基于已加载图谱数据进行过滤、BFS、路径搜索和交集计算实现。后端同时提供 /graph、/evidence-map 和 /graph/interventions 等接口，支持图谱数据获取和人工编辑。

输出结果

系统能够围绕目标对象、关键事件或侦查假设展示一跳关系、二跳扩展、多跳路径和交叉子图，辅助办案人员观察共同节点、关系路径、时间交叉和线索碰撞。

边界说明

当前图谱页的邻域扩展、多跳召回、子图交叉主要属于前端演示性图操作，不是完整后端图数据库查询；PPR 检索在 Agentic RAG / trace 中存在，但图谱页按钮本身未确认直接调用后端 PPR。

四、Agentic RAG 与任务化分析模块

模块目标

该模块用于解决大模型直接分析案件时证据范围不清、输出结构不稳定、结论难以核查的问题。系统通过检索计划、工具调用、证据组织和分析上下文构建，使大模型在任务约束和证据约束下生成分析结果。

实现方式

系统中的 Agentic RAG 检索计划器为 RetrievalPlannerService。它支持文档检索、图谱检索、节点扩展、时间范围检索、法律知识检索、规则包列表和规则包运行等工具。若模型配置可用，系统可调用 planner 模型生成 JSON 工具计划；若模型不可用或解析失败，则走 fallback 固定工具序列。检索过程被持久化为 RetrievalSession 和 RetrievalStep，并可在智能分析页面查看。

输出结果

系统可围绕用户提出的对象、行为、资金流、假设等问题，组织案件证据、图谱关系和法律知识，形成任务化分析上下文，再生成智能分析结果、行为还原、可疑信息和核查建议。

边界说明

系统对话入口采用 @... 作为任务上下文指定方式，可用于指定证据材料、法律知识和检察分析技能。检察 Skills 在后端以 list_rule_packs、run_rule_pack 等工具形式接入 Agentic RAG，前端可通过 @行为画像分析 等任务约束表达分析方向，并与规则包能力联动。

五、侦查画像生成模块

模块目标

该模块用于将案件证据、图谱关系、检索结果和法律知识整合为面向目标对象的侦查画像结果，支撑人物关系还原、行为方式分析和侦查参考建议生成。

实现方式

画像页面 Portrait.vue 调用 POST /cases/{case_id}/analysis/portrait-facts。后端 AnalysisService.portrait_facts 会调用 RetrievalPlannerService.run(mode="portrait")，收集 retrieval artifacts，再通过画像生成逻辑形成 PortraitFactsResult，前端展示人物关系、行为还原和证据溯源。画像输入包括案件标题、罪名、证据原文、抽取结果、图谱、Agentic RAG artifacts、法律知识 passages、图谱事实和文档检索 passage 等。

输出结果

画像结果包括 relationship_narrative、behavior_narrative、relationship_facts、behavior_facts、tool_calls、retrieval_session_id 等字段，对应人物关系还原、行为事实分析、可疑信息提示和画像建议。

六、证据溯源与人机协同模块

模块目标

该模块用于避免黑箱式智能输出，保证分析结论、画像事实和图谱关系能够回查原始材料和证据片段，并支持办案人员继续追问、人工修正和复核。

实现方式

智能分析句子使用 GroundedSentence.supporting_passages/supporting_graph_paths 保存来源，画像事实使用 PortraitFact.passages/evidence_ids 保存来源，画像报告 claim 使用 PortraitClaim.supporting_passages 保存支撑证据。图谱节点和边也可通过 evidence_ids 与证据原文关联，前端在 Intelligence.vue、Portrait.vue 和 Graph.vue 中提供溯源抽屉或详情面板。

输出结果

用户可以点击分析句、画像事实或图谱节点查看支撑证据、来源文件、证据片段和关系路径。需要说明的是，当前系统尽量将句子与 passage、图谱路径或 evidence_id 绑定，但并非所有生成句子都保证强证据支撑；若模型输出无法与 passage 匹配，支撑强度会降低或无支撑。

六、常见注意事项

  1. .doc 文件暂不支持，可优先使用 .docx、.pdf、.txt、.xlsx、.csv 等格式。
  2. 若模型 API Key 未配置，Agentic RAG planner 可能走 fallback 计划。
  3. 图谱页的邻域扩展、多跳召回、子图交叉当前主要是前端演示性图操作，不等同于完整后端图数据库查询。
  4. @... 可用于在对话中指定证据、法律知识和检察分析技能，便于把用户任务转化为有约束的分析流程。
  5. GNN 异常识别当前属于规划增强方向，演示中不应宣称已实现。

05_数据来源、合规与边界说明

一、数据来源说明

本项目演示数据主要来源于脱敏样本数据和模拟生成数据。仓库中包含 data/realtest、data/realcleantest、data/structured、data/legal_knowledge 等目录，其中 realcleantest 用于脱敏演示案件，structured 用于结构化流水、通话、时间线等样本，legal_knowledge 用于法律知识库和罪名模板支撑。

二、合规定位

系统定位为检察侦查辅助工具，仅用于依法立案侦查后，对依法调取的数据进行辅助处理、组织、分析和展示。系统不替代办案人员作出事实认定、法律判断或侦查结论，而是提供可回查、可复核、可修正的侦查参考信息。

三、证据处理原则

系统强调证据来源绑定和结果可回查。材料导入后，系统保存 evidence_id、原文内容、抽取结果、证据片段和图谱关系；在智能分析和画像生成中，系统尽量将结论句、画像事实和报告 claim 绑定到 supporting passages、graph paths 或 evidence_ids，从而降低黑箱式生成风险。

四、功能边界说明

当前系统已经实现多源材料导入、证据切片、三层证据图谱、智能分析、画像生成、证据溯源和人工编辑等功能；实体与事实关系抽取、Agentic RAG、检察分析 Skills、法律知识库和可疑资金流等已形成可演示链路；邻域扩展、多跳召回和子图交叉主要属于演示性前端图操作；跨案碰撞为原型实现；GNN 异常识别属于后续增强方向。

def route_extraction(source_type: str, content: str, raw_bytes: bytes | None = None,
                     filename: str | None = None, evidence_id: str | None = None) -> ExtractionResult:
    resolved = resolve_source_type(source_type, filename)
    if resolved in STRUCTURED_TYPES:
        rows = parse_structured_content(source_type=resolved, content=content, raw_bytes=raw_bytes)
        triples = map_rows_to_triples(rows, evidence_id=evidence_id, filename=filename)
        passages = build_passages_from_triples(triples)
        return ExtractionResult(triples=triples, passages=passages, metadata={"rows_count": len(rows)})

    triples, passages = extract_unstructured_triples(content, evidence_id=evidence_id)
    return ExtractionResult(triples=triples, passages=passages, metadata={"chars": len(content)})

说明：该片段体现系统对结构化材料和非结构化文本采取不同处理路径。流水、通话、时间线等结构化数据按行解析；笔录、文书等非结构化文本切分为 passage，并进入事实关系抽取链路。

def _ground_answer_sentences(answer: str, passages: list[TracePassage],
                             graph_context: list[str]) -> list[GroundedSentence]:

def apply_intervention(self, case_id: str, payload: GraphInterventionRequest) -> InvestigationGraph:
    graph = self.get_graph(case_id)
    if payload.action == "upsert_node" and payload.node:
        graph.nodes = [node for node in graph.nodes if node.node_id != payload.node.node_id]
        graph.nodes.append(payload.node)
    elif payload.action == "upsert_edge" and payload.edge:
        graph.edges = [edge for edge in graph.edges if edge.edge_id != payload.edge.edge_id]
        graph.edges.append(payload.edge)
    elif payload.action == "delete_node":
        graph.nodes = [node for node in graph.nodes if node.node_id != payload.node_id]
        graph.edges = [edge for edge in graph.edges if edge.source != payload.node_id and edge.target != payload.node_id]

说明：该片段体现系统支持办案人员对图谱节点和关系进行人工增删改查、复核和修正，保证算法抽取结果可以被人工校正。

def retrieve(self, query: str, offense_id: str | None = None, top_k: int = 8) -> TraceResult:
    docs, doc_titles = self._build_legal_docs(offense_id)
    terms = _query_terms(query)
    scored = []
    for index, doc in enumerate(docs):
        score = _score_text(doc, terms)
        if score > 0:
            scored.append((score, index, doc))
    scored.sort(key=lambda item: item[0], reverse=True)
    passages = [
        TracePassage(rank=rank + 1, score=score, evidence_id=f"legal_{index}",
                     title=doc_titles.get(str(index), "法律知识"), text=_shorten(doc, 600))
        for rank, (score, index, doc) in enumerate(scored[:top_k])
    ]
    return TraceResult(query=query, passages=passages, paths=[])

说明：该片段体现法律知识库可按罪名模板、流程知识和证据标准召回相关内容，为智能分析和画像报告提供法律实务上下文。

def run_rule_pack(self, case_id: str, pack_name: str) -> RulePackRunResult:
    checks = _load_checks(self.packs_dir, pack_name)
    mother_nodes = self.store.document_mother_nodes.get(case_id, [])
    evidence = self.store.evidence.get(case_id, [])
    findings: list[RuleFinding] = []
    not_triggered: list[NotTriggeredRule] = []
    for rule in checks.get("checks", []):
        result = self._evaluate_rule(rule, mother_nodes, evidence)
        if result:
            findings.append(result)
        else:
            not_triggered.append(NotTriggeredRule(rule_id=rule.get("id", ""), reason="当前证据结构未触发该规则"))
    return RulePackRunResult(skill_name=pack_name, findings=findings,
                             not_triggered=not_triggered, data_gaps=_data_gaps(mother_nodes))
