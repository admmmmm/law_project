处理层设计总览

处理层负责把依法调取的多源证据转化为系统可用的数据底座。系统以图谱作为关系组织核心，同时结合结构化数据表、文本检索索引和时间序列组织方式，共同支撑分析与碰撞。

Evidence → Ontology → Graph
从立案后已掌握的部分事实出发，对海量、多格式证据做统一读取、语义建模与图谱化落库。
01
Evidence

证据接入

把卷宗、笔录、文书、流水、通联、日志等不同来源数据统一读入系统。

  • 多格式接入
  • 文本与表格抽取
  • 基础清洗和标准化
→
02
Ontology

领域本体

把侦查场景里的对象和关系先定义清楚，形成统一语义结构。

  • 实体：人、案、账户、交易、行为
  • 关系：联系、转账、共同出现等
  • 本体不是从零自由生成
→
03
Graph

图谱构建

完成实体归并、关系去重、证据挂接和图数据库落库，形成后续查询与分析底座。

  • 可查
  • 可关联
  • 可追溯
输入

多源证据数据

案卷、流水、通联、日志、文书、身份和财产信息等。

原则

先验事实 + 统一语义

处理层默认存在部分已知实体与关系，不是从空白开始。

输出

多组织方式协同底座

以图谱组织关系，以结构化表管理字段，以文本索引追溯原文，以时间序列支撑时序分析。

边界说明

使用边界

依法立案侦查后 才进入系统分析流程。

部署方式

支持 本地化 / 私有化部署，适应涉密环境。

处理方式

可用 任务分工型 multi-agent / 多 worker 处理不同证据类型。

能力边界

处理层不直接生成犯罪定性结论。
