# 基础办案知识库

这个目录保存系统第一版办案知识 seed。它的定位不是替代检察官判断，而是给系统提供三个稳定支点：

1. 案件创建时：按罪名加载“要查什么”的核查模板。
2. 证据接入时：把证据类型、事实片段、图谱节点关联到具体构成要件。
3. 生成报告时：让每个分析结论能回到对应要件、证据和法律来源。

## 目录

- `sources.json`：官方法律和办案规范来源索引。为避免复制整篇网页，当前保存官方链接、用途和结构化摘要。
- `template_schema.json`：分罪名模板字段规范，供检察官自定义和 AI 优化时保持格式一致。
- `evidence_type_mapping.json`：证据类型到要件、风险线索、推荐问题的映射。
- `alias_resolution_rules.json`：别名、假名、马甲账号的合并建议规则。
- `offense_templates/xunsi_wangfa.json`：徇私枉法罪第一版可用模板。

## 使用方式

后端提供 `/api/v1/legal-knowledge/*` 只读接口读取这些 seed。后续可以加管理接口，让检察官在案件空间内复制一份模板并修改，不直接覆盖基础模板。

## 重要原则

- 高置信身份信息可以自动合并，例如同一身份证号、同一实名银行卡、同一手机号。
- 低置信线索只生成“合并建议”，例如共同设备、交易习惯、密集通话、同一地点出现。
- 构成要件核查不只看是否出现关键词，要保留证据出处、原文片段、反证和缺口。
- 法律来源以官方链接为准；本库只存摘要和检索索引。
