04

处理层设计

处理层负责把依法调取的多源证据数据转化为统一语义、统一结构、统一关系的侦查图谱，不直接做案件定性，而是为后续分析与碰撞提供可追溯底座。

Evidence → Ontology → Graph
处理层的任务不是“简单读文件”，而是把原始证据材料转成可计算、可关联、可查询的侦查图谱数据底座。
01
证据解析

多格式证据接入与标准化

面向 PDF、Word、Excel、CSV、流水、日志、OCR 文本等多源材料完成统一解析，把非结构化文本和结构化记录都转成可继续处理的标准化中间数据。

  • 完成文本提取、字段清洗、时间归一与来源标注
  • 兼顾案卷材料、通联记录、交易数据、行为日志等异构输入
  • 形成后续实体与关系抽取可直接使用的数据入口
→
02
领域本体

已有侦查事实 + 本体扩展建模

本体建模并不是从零自由生成，而是在案件已经立案、已有部分 entity 和 relation 的前提下，对案件、人员、账户、交易、行为、时间节点等核心对象进行统一建模。

  • 接住已知案件、嫌疑人、关系人、账户和交易链条
  • 由 LLM 在此基础上补充未被显式标出的实体与关系
  • 形成侦查场景统一的 schema，支撑后续图谱构建
→
03
图谱构建

实体归并、关系落库与证据挂接

将抽取结果真正转化为侦查图谱，完成节点、边、来源证据和对象归并，使后续图谱查询、专题报告、信息画像与建议生成建立在可追溯关系网络之上。

  • 实体去重与同名归并，避免关系网络碎片化
  • 关系落库并挂接来源证据，保留可解释链路
  • 形成后续分析与碰撞层可直接调用的查询底座
Input

多源证据数据

案卷文本、交易流水、通联记录、行为日志、文书材料等统一接入，支撑真实侦查场景下的大规模数据处理。

Core

结构化处理能力

以标准化、本体建模和图谱构建为核心，把异构证据材料转成统一语义对象与关系网络。

Output

可查询图谱底座

输出多维实体节点、关系边与来源证据，为后续分析、碰撞、画像和建议生成提供标准支撑。

设计原则

从“立案后已有事实”出发

  • 系统启动时通常已经存在部分已知人物、账户、案件节点和关系链。
  • 处理层需要先接住这些已知事实，再由模型辅助补充潜在 entity 与 relation。
  • 这样既符合侦查实际，也避免把领域本体做成脱离业务场景的空模型。
实现方式

本地部署 + 多模块并行

  • 考虑涉密或半涉密环境，模型与系统支持本地化或私有化部署。
  • 面对海量证据，可采用任务分工型 multi-agent / 多 worker 方式并行处理不同类型数据。
  • LLM 负责结构化补全和语义归纳，后端负责校验、汇总与落库。
边界说明

处理层不做什么

  • 不直接生成案件定性判断
  • 不替代侦查人员作出法律结论
  • 不直接输出嫌疑人认定结果
