## 案例设计
关于画像。第一层: 基础信息聚合
  "这个人是谁、在哪工作、有什么职权"
  → 解决主体要件
  → 任何系统都能做
还有人物关系要有

第二层: 行为事实还原
  "这个人做了什么、和谁有关联、资金怎么流的"
  → 解决客观要件
  → 碰撞能力在这里发挥作用
**这里不能漏掉行为方式**
行为方式是找一找当事人可能在哪做了隐瞒或者反侦察的操作，因为基本目标人多多少少都具备反侦察意识。

**第三层: 主观方面推理**    
  "这个人知不知道、故意还是过失、对结果什么态度"
  → 解决主观要件
  → 从证据推理出法律上的主观状态
  → 这是定罪的关键，也是最难的部分

目前的分析和画像整体来说都很差劲。为什么呢？
画像报告不是 DeepSeek 直接认真写的。
backend/app/services/report_service.py 现在主要是把 graph.clues、节点数、关系数、资金线索、职责线索拼进固定模板。DeepSeek/HippoRAG 的 QA 结果如果有，会作为 clue 混进去，但报告本身不是一次完整的“基于证据生成画像报告”。

“分析”现在主要是规则线索。
backend/app/adapters/algorithm.py 里的 _clues_from_graph() 会扫关键词，比如“立案、拘留、释放、调解、现金、转账、明知、请托”。扫到就生成一句模板化描述。
所以会出现那种：
“已从结构化流水中聚合出 12 条资金相关关系……”
这不是法律分析，是统计提示。

结构化流水权重太高，压过案情。
后端图谱把银行流水聚合进来后，很容易产生大量金额、交易关系。画像页又直接拿这些聚合结果当“职权范围/主观方面/结果因果”的材料，所以会出现“主观方面”和“结果因果”写得一模一样的情况。

字段没有真正对应“要件”。
现在的“主体要件、客观行为、主观方面、结果因果”不是模型逐项核查后写出来的，而是前端/后端用关键词去填。
所以它缺少你要的逻辑：
“这个要件需要什么 → 当前证据有哪些 → 缺什么 → 可能抗辩是什么”。

溯源粒度还不够细。
现在点击一句话，本质是拿这句话再去 PPR 检索，而不是“这句话生成时就绑定了哪些 passage”。

如果能解决阿加莎的文本，比如一本书扔进去（除了最后一章或者最后几章），然后让我们的系统分析，还原人物关系，梳理案件线索，确定犯罪嫌疑人的行为，提取可疑信息，就人物关系及其行为方式提供画像和参考建议，进而帮助查明案情。那就很棒了。
