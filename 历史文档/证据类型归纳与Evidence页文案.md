# 证据类型归纳与 Evidence 页文案

## 1. 这一页要解决什么问题

在处理层中，`Evidence` 这一步的核心不是讲复杂算法，而是先让评委和队员明白：

- 系统面对的到底是什么样的数据
- 为什么这些数据会“海量、异构、难处理”
- 为什么后面一定需要本体建模和图谱构建

所以这一页的作用是：

**把“依法调取的数据”具体化，把处理层的输入边界讲清楚。**

---

## 2. 可以怎样概括 Evidence 输入

可以先用一句总括性表述：

**本系统面向依法立案侦查后依法调取的多源证据数据，既包括大量非结构化材料，也包括可直接计算的结构化业务数据。**

再往下拆成两类：

- **非结构化证据材料**
- **结构化业务数据**

这样最清楚，也最符合你们后面“解析 -> 本体 -> 图谱”的处理逻辑。

---

## 3. 非结构化证据材料

这类数据的特点是：

- 内容丰富，但不规整
- 很多信息藏在长文本、附件、音视频说明里
- 人工阅读成本高，难以直接用于批量分析

### 3.1 检察、公安侦查相关材料

- 公安侦查卷
- 讯问笔录
- 同步录音录像
- 鉴定意见
- 搜查笔录
- 扣押清单

### 3.2 法院审判与执行相关材料

- 法院判决书
- 裁定书
- 庭审记录
- 执行材料

### 3.3 监察机关相关材料

- 监察委留置笔录
- 谈话录音
- 涉案财物清单

### 3.4 这类材料对系统意味着什么

这类数据往往承载着：

- 案件经过
- 人员身份信息
- 供述与陈述
- 时间节点
- 财物线索
- 行为描述

但问题在于，它们通常是：

- PDF
- Word
- 图片 OCR 结果
- 音视频转写文本

因此第一步必须先做：

- 文本抽取
- 表格识别
- 字段清洗
- 关键信息提取

---

## 4. 结构化业务数据

这类数据的特点是：

- 字段相对固定
- 更适合统计、筛选、比对和碰撞
- 是后续关系分析、资金分析、时间线分析的重要基础

### 4.1 通联与社交数据

- 通话详单：号码、时间、时长、频次、主叫、被叫
- 短信 / 彩信记录
- 微信聊天记录
- QQ 聊天记录
- 钉钉聊天记录
- 图片、文件、转账记录

这些数据可以支撑：

- 联系频次分析
- 关键时间段通信行为分析
- 人物关系链发现

### 4.2 上网与设备记录

- IP 信息
- 浏览记录
- 登录设备
- 登录时间

这些数据可以支撑：

- 行为轨迹还原
- 登录习惯分析
- 关键节点前后的设备使用情况分析

### 4.3 银行与支付数据

- 银行流水：个人账户、公司账户、转账、取现、理财、基金、外汇、贵金属
- 支付宝交易记录
- 微信支付交易记录
- 收款方、付款方、时间、金额

这些数据可以支撑：

- 可疑资金流动分析
- 账户关联分析
- 资金链条追踪

### 4.4 证券、期货、股票等金融数据

- 开户信息
- 交易记录
- 持仓信息
- 分红信息
- 资金划转记录

这些数据可以支撑：

- 隐性利益输送线索发现
- 复杂金融路径分析

### 4.5 身份与社会属性数据

- 户籍信息
- 身份证
- 户口本
- 出入境记录
- 护照
- 港澳通行证

这些数据可以支撑：

- 身份确认
- 行程与跨境行为辅助分析

### 4.6 社会关系与财产属性数据

- 婚姻信息
- 房产信息
- 车辆信息
- 工商信息
- 税务信息
- 社保信息
- 公积金信息

这些数据可以支撑：

- 密切关系人识别
- 财产关联分析
- 家庭与社会关系网络还原

### 4.7 保险、信托、理财类数据

- 投保信息
- 理赔信息
- 收益情况
- 资金流向

这些数据可以支撑：

- 资产配置路径分析
- 间接利益链发现

---

## 5. 为什么这些数据会构成“处理层难点”

可以用一段话概括：

**这些证据和业务数据的难点，不在于单条数据看不懂，而在于来源多、格式杂、体量大、字段不统一、隐藏关系深。只有先完成读取、清洗、标准化和结构化，后续本体建模、图谱构建、分析碰撞和画像生成才有可能成立。**

---

## 6. 可以直接放进 PPT 的短版文案

### 版本 A：较正式

本系统面向依法立案侦查后依法调取的多源证据数据，输入既包括公安侦查卷、讯问笔录、同步录音录像、判决裁定文书、留置笔录、涉案财物清单等非结构化材料，也包括通话详单、聊天记录、上网记录、银行流水、支付记录、证券交易、身份户籍、婚姻房产、工商税务、社保公积金等结构化业务数据。其共同特点是来源多、格式杂、体量大、语义分散，因此必须先经过统一读取、清洗、标准化和结构化处理，才能进入后续的领域本体建模与图谱构建阶段。

### 版本 B：适合页面短句

- 输入不是单一文本，而是多源证据数据集合  
- 既有卷宗、笔录、文书、音视频转写等非结构化材料  
- 也有通联、支付、银行、证券、身份、房产等结构化数据  
- 难点在于来源分散、格式异构、体量庞大、关系隐蔽  
- 因此必须先做统一读取、清洗和结构化处理

## 7. 如果要做 Evidence 页，页面上可以怎么摆

如果后面你们真的要做一张 `Evidence` 页，最稳的结构是：

### 左侧：非结构化证据材料

- 公安侦查卷
- 讯问笔录
- 同步录音录像
- 鉴定意见
- 搜查笔录
- 判决书 / 裁定书 / 庭审记录
- 留置笔录 / 谈话录音 / 财物清单

### 右侧：结构化业务数据

- 通话详单 / 聊天记录 / 上网记录
- 银行流水 / 支付记录 / 证券期货
- 身份户籍 / 出入境 / 婚姻房产 / 工商税务 / 社保公积金
- 保险 / 信托 / 理财

### 底部总结句

**Evidence 层的任务，是把“材料”和“数据”一起接进来，为后续本体建模和图谱构建准备统一输入。**
