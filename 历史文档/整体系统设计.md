# 整体系统设计

## 1. 系统总目标

本系统面向检察侦查场景，服务于**依法立案侦查后**对司法工作人员职务犯罪相关信息、数据的处理、分析、碰撞与辅助研判。

系统的总体目标不是替代侦查判断，而是提供一套：

- 能接入多源证据数据
- 能构建侦查关系图谱
- 能完成专题分析与交叉碰撞
- 能输出参考信息、信息画像和参考建议

的智能分析辅助平台。

## 2. 系统总体思路

如果把整个系统压缩成一条主链路，就是：

**证据接入 -> 处理层 -> 分析与碰撞层 -> 图谱查询与报告生成 -> 信息画像与参考建议输出**

换句话说，系统不是单点功能，而是一条从原始数据到侦查辅助结果的完整工作流。

## 3. 系统整体分层

建议把系统分成五层：

1. **证据接入层**
2. **处理层**
3. **分析与碰撞层**
4. **输出生成层**
5. **展示与交互层**

## 4. 第一层：证据接入层

这一层负责把依法调取的多源数据接入系统。

### 输入对象

- PDF
- Word
- TXT
- Excel
- CSV
- OCR 文本
- 银行流水
- 通联记录
- 出入记录
- 操作日志

### 核心任务

- 文件读取
- 文本提取
- 表格解析
- 字段标准化
- 数据来源标注

### 这一层的作用

把原始证据材料从“不可直接分析”变成“可继续处理”的中间数据。

## 5. 第二层：处理层

处理层是整个系统的技术底座，主要包含三步：

1. **解析证据**
2. **生成领域本体**
3. **图谱构建**

### 1. 解析证据

把非结构化文本和结构化记录统一清洗、切块、标准化。

### 2. 生成领域本体

定义侦查场景中的核心对象和核心关系，例如：

- 案件
- 犯罪嫌疑人
- 密切关系人
- 账户
- 交易
- 行为事件
- 时间节点

### 3. 图谱构建

把证据数据和领域本体结合，构建：

- 实体节点
- 关系边
- 来源证据
- 可查询的侦查图谱

### 这一层的作用

形成后续分析与碰撞可依赖的数据底座。

## 6. 第三层：分析与碰撞层

这一层是系统的核心业务层。

这里把“分析”和“碰撞”视为同一层中的两类核心能力：

- **分析**：从图谱中提炼人物、资金、行为、时间等规律
- **碰撞**：让不同来源、不同类型数据交叉验证，发现异常与关键关联

### 主要分析方向

- 人物关系分析
- 资金流动分析
- 人员行为分析
- 时间线分析

### 主要碰撞方向

- 人物与资金碰撞
- 人物与行为碰撞
- 资金与时间碰撞
- 行为与时间碰撞
- 关系网络与资金网络碰撞

### 这一层的作用

从图谱中提炼出真正可用于研判的异常线索和重点对象。

## 7. 第四层：输出生成层

输出生成层负责把前面的分析结果转成可阅读、可汇报、可展示的成果。

这一层建议包含四个核心模块：

### 模块 1：图谱查询

这是基础功能，负责：

- 按人物查询
- 按账户查询
- 按案件查询
- 按时间查询
- 按关系类型查询

### 模块 2：专题报告生成

负责生成不同线路的分析报告，包括：

- 人物关系报告
- 资金流动报告
- 行为分析报告
- 时间线报告
- 多线路组合报告

报告生成链路建议为：

**图谱查询 -> 结果组织 -> 模板化结构 -> LLM 归纳成文**

### 模块 3：信息画像

面向题目要求中的：

- 犯罪嫌疑人画像
- 密切关系人画像

画像内容建议覆盖：

- 基本身份
- 案件关联
- 核心关系网络
- 账户与交易特征
- 行为特征
- 时间节点特征
- 异常线索摘要

### 模块 4：参考建议生成

参考建议不能凭空生成，而应来自：

**图谱查询结果 + 碰撞结果 + 画像结果**

建议内容包括：

- 优先核查对象
- 优先关注账户
- 关键时间窗口
- 重点复核关系链

## 8. 第五层：展示与交互层

这一层是系统的用户界面层，主要面向申报展示和答辩演示。

### 设计原则

- 简洁直观
- 操作便捷
- 重点突出
- 支持大规模数据场景的表达

### 前端建议展示内容

- 数据上传与导入
- 图谱关系网络
- 图谱查询结果
- 专题报告结果
- 信息画像卡片
- 参考建议摘要

### 这一层的作用

把复杂的后台分析结果转成评委和用户一眼能理解的系统表现。

## 9. 系统中的技术角色分工

从技术功能上看，系统里可以有四类核心能力：

### 1. 规则与处理能力

负责：

- 字段清洗
- 标准化
- 条件过滤
- 碰撞规则判断

### 2. 图谱能力

负责：

- 关系组织
- 关系查询
- 路径还原
- 多对象关联表达

### 3. LLM 能力

负责：

- 本体扩展
- 结果归纳
- 报告生成
- 画像生成
- 建议生成

### 4. 工作流型 multi-agent 能力

- 证据解析 agent
- 实体抽取 agent
- 关系抽取 agent
- 图谱查询 agent
- 报告生成 agent
- 审核校验 agent

它们的作用是：

- 并行处理大规模证据
- 拆分复杂任务
- 提升系统吞吐量
- 让结果链路更清晰

## 10. 建议的整体技术架构

从工程上，建议采用：

- **前后端分离架构**
- 前端负责交互与展示
- 后端负责处理、分析、图谱、生成

### 前端

建议基于现代框架实现：

- 数据上传页面
- 图谱可视化页面
- 查询与筛选页面
- 报告与画像页面

### 后端

建议负责：

- 证据解析
- 数据标准化
- 领域本体管理
- 图谱构建与查询
- 专题分析
- 报告生成
- 画像与建议生成

### 模型部署

考虑场景可能涉及涉密或半涉密内容，系统在方案上应强调：

- 支持本地部署或私有化部署模型
- 支持内网闭环运行
- 支持证据数据本地处理

## 11. 系统最终输出什么

整个系统最终面向侦查人员输出三类结果：

### 1. 参考信息

- 关键人物关系链
- 可疑资金流向
- 异常行为节点
- 关键时间窗口

### 2. 信息画像

- 犯罪嫌疑人画像
- 密切关系人画像
- 账户画像
- 行为画像

### 3. 参考建议

- 优先核查对象建议
- 优先关注账户建议
- 时间窗口复核建议
- 关系链重点审查建议

## 12. 一句话总结

本系统的整体设计，不是做一个泛化 AI 产品，而是围绕检察侦查场景，构建一套从证据接入、图谱构建、分析碰撞到报告、画像、建议输出的完整智能分析辅助系统。
