
# Case Space 案件空间前两个板块详细设计说明

> 适用范围：本说明用于案件空间 Case Space 的第一阶段前端重设计。
>
> 本阶段只处理两个板块：
>
> 1. 案件概览
> 2. 案件证据地图
>
> 本阶段暂不要求重做：
>
> - 智能分析
> - 信息画像
>
> 设计目标：
>
> 把用户进入某一个案件后的页面，从“功能堆叠”整理成“单案工作空间”。用户应当能快速理解当前案件的基础情况、证据导入情况、图谱构建状态，并进入证据地图查看文件、片段和事实关系。

---

# 1. 案件空间 Case Space 总体设计

## 1.1 案件空间定位

案件空间是用户选择某一个案件后进入的专属工作区。

它不同于 Workspace 工作台。

```text
Workspace 工作台：
  面向全局，不绑定具体案件。
  负责：我的案件、新建案件、检察技能库、知识库、设置。

Case Space 案件空间：
  面向单个案件，所有页面都围绕当前案件展开。
  负责：案件概览、案件证据地图、智能分析、信息画像。
````

一句话定位：

```text
案件空间是单个案件的办案工作区。
```

用户进入案件空间后，应该能清楚回答：

```text
我现在在哪个案件？
这个案件处理到哪一步了？
已经导入了哪些证据？
证据之间是什么结构？
下一步应该做什么？
```

---

## 1.2 案件空间主板块

案件空间左侧竖列卡片固定为：

```text
案件概览
案件证据地图
智能分析
信息画像
```

本阶段详细设计：

```text
案件概览
案件证据地图
```

本阶段暂时保持现状：

```text
智能分析
信息画像
```

# 2. 案件空间统一布局

## 2.1 页面整体结构

案件空间页面统一采用三块区域：

```text
左侧竖列卡片区
顶部工具区
右下主功能区
```

结构示意：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 顶部工具区：案件空间 / 当前案件 / 当前页面 / 页面操作按钮            │
├────────────────┬───────────────────────────────────────────────────┤
│ 左侧竖列卡片区  │                                                   │
│                │                                                   │
│ 案件概览        │                                                   │
│ 案件证据地图    │                  主功能区                         │
│ 智能分析        │                                                   │
│ 信息画像        │                                                   │
│                │                                                   │
└────────────────┴───────────────────────────────────────────────────┘
```

## 2.2 三个区域的职责

### 左侧竖列卡片区

负责：

```text
用户要进入案件空间的哪个模块。
```

例如：

```text
案件概览
案件证据地图
智能分析
信息画像
```

其中案件证据地图有子卡片：

```text
文件证据图
片段证据图
原始图谱层
```

### 顶部工具区

负责：

```text
显示当前页面标题、当前案件信息、当前页面操作按钮。
```

顶部工具区不负责模块切换。

特别注意：

```text
案件证据地图页中，图层切换已经由左侧栏完成。
顶部工具区不再出现“文件证据图 / 片段证据图 / 原始图谱层”切换按钮。
```

### 主功能区

负责：

```text
当前页面的核心业务内容。
```

例如：

```text
案件概览页：案件信息、统计、证据列表、推荐下一步。
案件证据地图页：图谱画布、图谱图例、右侧详情栏。
```

# 3. 案件空间左侧竖列卡片

## 3.1 左侧卡片内容

案件空间左侧卡片按照办案流程排列：

```text
案件概览
案件证据地图
智能分析
信息画像
```

建议每张卡片包含：

```text
图标
标题
一句话说明
状态 / 数量
子卡片，如果有
```

示例：

```text
┌────────────────────┐
│ 案件概览             │
│ 查看案件状态与进度     │
│ 当前阶段：辅助分析中   │
└────────────────────┘

┌────────────────────┐
│ 案件证据地图         │
│ 查看证据结构与事实关系 │
│ 3 类图谱             │
│  - 文件证据图        │
│  - 片段证据图        │
│  - 原始图谱层        │
└────────────────────┘

┌────────────────────┐
│ 智能分析             │
│ 围绕证据进行辅助分析   │
│ 本阶段保持现状        │
└────────────────────┘

┌────────────────────┐
│ 信息画像             │
│ 关系画像与行为画像     │
│ 本阶段保持现状        │
└────────────────────┘
```

---

## 3.2 左侧卡片交互规则

```text
1. 案件概览没有子卡片，点击后进入案件概览页。
2. 案件证据地图有三个子卡片，点击一级卡片时展开或收起。
3. 案件证据地图的三个子卡片分别是：
   - 文件证据图
   - 片段证据图
   - 原始图谱层
4. 点击案件证据地图的子卡片后，主功能区切换对应图谱。
5. 智能分析本阶段不展开子卡片。
6. 信息画像本阶段不展开子卡片。
7. 当前所在一级卡片高亮。
8. 当前所在子卡片高亮。
9. 左侧卡片不要暴露技术调试项。
10. 左侧卡片不要出现点击后无效的入口。
```

---

## 3.3 左侧卡片状态显示建议

每个卡片可以显示一个简短状态。

### 案件概览

```text
当前阶段：材料整理中 / 辅助分析中 / 待复核
```

### 案件证据地图

```text
文件 18｜片段 276｜事实 144
```

### 智能分析

```text
分析会话 6
```

### 信息画像

```text
画像已生成 / 未生成
```

如果第一阶段数据不好取，可以先使用简化状态：

```text
未开始
已生成
处理中
待复核
```

# 4. 案件空间顶部工具区通用规则

## 4.1 顶部工具区基础结构

顶部工具区每个页面都应显示：

```text
当前位置
当前案件名称
case_id
当前页面标题
当前页面主操作
服务状态
```

示例：

```text
案件空间 / 舞王俱乐部案 / 案件概览

case_id：case_632371a3a613
当前阶段：辅助分析中
服务状态：正常

[刷新状态] [进入下一步]
```

证据地图页示例：

```text
案件空间 / 舞王俱乐部案 / 案件证据地图 / 文件证据图

[树形] [力导] [导出截图]
```

---

## 4.2 顶部工具区原则

```text
1. 顶部只放当前页面相关操作。
2. 顶部不负责左侧模块切换。
3. 顶部不要堆满所有功能按钮。
4. 顶部不要显示调试日志。
5. 顶部不要显示 G6 / RelationGraph 等技术名。
6. 服务状态可以保留，但要弱化，不要抢主视觉。
7. 案件证据地图页中，图层切换只在左侧栏完成。
```

# 5. 板块一：案件概览

## 5.1 页面定位

案件概览是用户进入某个案件后的首页。

它不是 Workspace 的“我的案件”。

它负责展示：

```text
当前案件基础信息
当前案件处理进度
已导入证据列表
已生成分析 / 画像 / 报告统计
推荐下一步
```

一句话定位：

```text
案件概览页是单个案件的工作台首页。
```

它回答三个问题：

```text
这个案件是什么？
现在处理到哪一步？
下一步应该做什么？
```

---

## 5.2 页面入口

建议新路径：

```text
/cases/:caseId
```

进入某个案件后默认打开案件概览页。

如果保留旧 workspace 路由，也可以兼容，但新的 UI 导航应优先进入：

```text
/cases/:caseId
```

---

## 5.3 页面整体结构

案件概览页主功能区建议分为六块：

```text
1. 当前案件标签 / 案件标题
2. 案件基础信息
3. 案件进度统计
4. 推荐下一步
5. 已导入证据
6. 最近活动 / 最近生成内容，可选
```

结构示意：

```text
┌──────────────────────────────────────────────────────────────┐
│ CASE 1：舞王俱乐部案                                           │
│ case_id：case_632371a3a613                                      │
├──────────────────────────────────────────────────────────────┤
│ 基础信息                                                        │
│ 名称 / 嫌疑人 / 罪名 / 当前阶段 / 最近更新时间                   │
├──────────────────────────────────────────────────────────────┤
│ 统计卡片                                                        │
│ 已导入证据 18 | 图谱节点 144 | 已生成分析 6 | 已生成画像 2         │
├──────────────────────────────────────────────────────────────┤
│ 推荐下一步                                                      │
│ 当前已完成证据地图构建，建议继续进行智能分析。 [开始智能分析]       │
├──────────────────────────────────────────────────────────────┤
│ 已导入证据                                                      │
│ 证据状态筛选 + 证据列表                                          │
└──────────────────────────────────────────────────────────────┘
```

---

## 5.4 左侧卡片状态

左侧卡片中显示：

```text
案件概览
查看案件状态与处理进度
```

当前页面时高亮。

案件概览没有子卡片。

## 5.5 顶部工具区

顶部标题：

```text
案件概览
```

说明文字：

```text
查看当前案件的基础信息、证据导入情况、图谱构建状态和后续处理入口。
```

右侧按钮建议：

```text

```

如果暂时无法实现“进入下一步”自动判断，可以先保留：

```text

```

或者显示：

```text
[刷新状态] [查看证据地图]
```

## 5.6 当前案件标签

手绘原型中有一个：

```text
CASE 1 ×
```

这个可以保留为案件标签设计。

### 第一阶段建议

先简化为展示当前案件，不一定做真正多案件标签管理。

显示：

```text
CASE 1：舞王俱乐部案
```

或：

```text
当前案件：舞王俱乐部案
```

### 如果实现关闭按钮

```text
[CASE 1 ×]
```

关闭按钮含义：

```text
关闭当前案件空间，返回“我的案件”。
```

注意：

```text
第一阶段不建议做复杂多案件标签。
可以只展示当前案件名称，不实现多标签切换。
```

## 5.7 案件基础信息区

### 5.7.1 必须展示字段

手绘原型中的核心字段：

```text
名称
嫌疑人
罪名
```

建议补充字段：

```text
case_id / 案号
当前阶段
最近更新时间
案件类型
承办部门，可选
承办人员，可选
```

### 5.7.2 字段表

| 字段           | 说明           | 是否必须 |
| ------------ | ------------ | ---- |
| 案件名称         | 当前案件名称       | 必须   |
| case_id / 案号 | 案件唯一标识       | 必须   |
| 嫌疑人          | 涉案人员，可为空     | 建议   |
| 罪名 / 案件类型    | 当前案件关联罪名模板   | 建议   |
| 当前阶段         | 材料整理中、辅助分析中等 | 建议   |
| 最近更新时间       | 最近导入、分析或修改时间 | 建议   |
| 承办部门         | 如后端有字段则展示    | 可选   |
| 承办人员         | 如后端有字段则展示    | 可选   |

### 5.7.3 UI 示例

```text
┌──────────────────────────────────────────────┐
│ 舞王俱乐部案                                  │
│ case_id：case_632371a3a613                    │
│                                              │
│ 嫌疑人：张某、李某                             │
│ 罪名：徇私枉法 / 滥用职权相关线索                │
│ 当前阶段：辅助分析中                            │
│ 最近更新：2026-05-14 19:11                     │
└──────────────────────────────────────────────┘
```

## 5.8 案件阶段设计

案件阶段建议统一为以下几种：

```text
材料整理中
证据地图已生成
辅助分析中
待复核
已归档
```

使用方式：

```text
当前阶段：辅助分析中
```

不要混用太多状态词，比如：

```text
处理中
active
done
图谱完成
已分析
```

统一命名更利于前端展示。

## 5.9 案件进度统计区

手绘图里有两个统计项：

```text
已生成报告 NUM
已生成分析 NUM
```

建议扩展为四个统计卡片，以体现案件全流程：

```text
已导入证据
图谱节点
已生成分析
已生成画像 / 报告
```

### 5.9.1 第一阶段推荐统计项

```text
已导入证据
图谱节点
已生成分析
已生成画像
```

如果报告功能已有，则可以改为：

```text
已导入证据
图谱节点
已生成分析
已生成报告
```

### 5.9.2 UI 示例

```text
┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│ 已导入证据  │ │ 图谱节点     │ │ 已生成分析  │ │ 已生成画像  │
│ 18         │ │ 144        │ │ 6          │ │ 2          │
└────────────┘ └────────────┘ └────────────┘ └────────────┘
```

### 5.9.3 统计项点击交互，可选

```text
点击“已导入证据” → 滚动到证据列表
点击“图谱节点” → 进入案件证据地图
点击“已生成分析” → 进入智能分析
点击“已生成画像” → 进入信息画像
```

第一阶段不强制实现点击，但可以预留。

## 5.10 推荐下一步区

案件概览页建议增加“推荐下一步”。

它用于告诉用户当前案件下一步该做什么。

### 5.10.1 推荐规则

```text
如果没有证据：
  下一步：导入证据

如果有证据但没有图谱：
  下一步：构建案件证据地图

如果有图谱但没有分析：
  下一步：开始智能分析

如果有分析但没有画像：
  下一步：生成信息画像

如果已有画像：
  下一步：查看画像或生成报告
```

### 5.10.2 UI 示例

```text
推荐下一步

当前案件已导入 18 份证据，并完成证据地图构建。
建议继续进行智能分析，检查是否存在证据矛盾或可疑行为线索。

[开始智能分析]
```

### 5.10.3 如果第一阶段不做自动判断

可以先做静态区域：

```text
推荐下一步

你可以继续查看案件证据地图，或进入智能分析页面进行辅助分析。

[查看证据地图] [开始智能分析]
```

## 5.14 证据列表条目设计

证据列表使用长条卡片或紧凑列表。

每条证据建议展示：

```text
证据名称 NAME
证据摘要 BRIEF
证据 ID
证据类型
处理状态
导入时间
```

手绘图中特别强调：

```text
NAME
BRIEF
ID
```

这三个字段必须能看到。

### 5.14.1 证据条目示例

```text
┌────────────────────────────────────────────────────┐
│ 舞王俱乐部《营业执照》（副本）              已解析    │
│ ID：evd_a9b8e002680e                              │
│ 类型：工商登记材料                                  │
│ 摘要：证明舞王俱乐部登记名称、经营者、经营范围等        │
│                                                    │
│ [查看详情] [进入审阅] [在地图中定位]                  │
└────────────────────────────────────────────────────┘
```

### 5.14.2 证据列表滚动

如果证据较多，证据区内部支持滚动。

要求：

```text
1. 证据区内部可滚动。
2. 页面整体不要因为证据列表过长而失控。
3. 滚动条样式不要过于抢眼。
4. 列表条目高度保持稳定。
```

## 5.15 点击证据后的交互

点击证据条目后，应显示证据关键信息。

### 5.15.1 推荐交互：右侧详情抽屉

点击证据条目后，从右侧打开详情抽屉。

详情字段：

```text
证据名称 NAME
证据摘要 BRIEF
证据 ID
证据类型
证明事项
处理状态
导入时间
所属案件
```

操作按钮：

```text
[进入证据审阅]
[在证据地图中定位]
[加入智能分析]
```

### 5.15.2 备选交互：内联展开

如果不做右侧抽屉，也可以在证据条目下方展开详情。

但更推荐右侧抽屉，因为后续智能分析和画像页也会使用类似右侧溯源面板。

## 5.16 证据审阅页入口

点击：

```text
[进入审阅]
```

建议跳转：

```text
/cases/:caseId/evidence/:evidenceId
```

# 6. 板块二：案件证据地图

## 6.1 页面定位

案件证据地图页是当前案件的证据结构展示页。

它用于查看：

```text
文件证据之间的组织关系
证据片段之间的支撑关系
原始事实图谱中的节点和关系
```

本阶段不是重做图谱，而是对现有图谱页做简化和整理。

一句话定位：

```text
案件证据地图页用于查看当前案件的三类图谱，并只在原始图谱层维护节点和关系。
```

---

## 6.2 本阶段设计目标

```text
1. 简化页面。
2. 修正图例。
3. 保留树形 / 力导切换。
4. 在布局切换旁边增加导出截图按钮。
5. 图谱区域必须显示图谱图例。
6. 右侧信息栏大幅简化。
7. 保留点击节点 / 边后在右侧显示详情。
8. 增删改查只在原始图谱层提供。
9. 文件证据图和片段证据图保持只读。
10. 普通界面隐藏调试日志和技术细节。
```

---

## 6.3 页面入口

建议路径：

```text
/cases/:caseId/graph
```

三类图谱由左侧栏子卡片控制。

# 10. 编辑功能范围

## 10.1 核心规则

非常重要：

```text
增删改查只在原始图谱层提供。
```

具体规则：

```text
文件证据图：只读，不提供节点/边编辑。
片段证据图：只读，不提供节点/边编辑。
原始图谱层：可新增、编辑、删除节点和关系。
```

原因：

```text
文件证据图和片段证据图是证据结构展示层。
原始图谱层是事实关系维护层。
```

---

## 10.2 文件证据图和片段证据图的右侧提示

在文件证据图和片段证据图中，右侧不出现编辑表单。

可以在右侧信息栏底部显示简短提示：

```text
该图层用于查看证据结构，不支持直接编辑。
如需维护事实关系，请切换到原始图谱层。
```

不要放成醒目的警告，只做轻提示。

# 11. 原始图谱层编辑区

## 11.1 编辑区出现条件

当当前左侧选中：

```text
原始图谱层
```

右侧信息栏下方显示编辑区。

当当前左侧选中：

```text
文件证据图
片段证据图
```

右侧不显示编辑区。

---

## 11.2 原始图谱层：未选中对象

显示：

```text
原始图谱维护

请选择一个节点或关系进行编辑。
```

操作按钮：

```text
[新增节点]
[新增关系]
```

按钮位置：

```text
右侧信息栏下方
```

不要放到图谱画布中央。

---

## 11.3 原始图谱层：选中节点

右侧上半部分显示节点详情。

下半部分显示编辑节点表单。

表单标题：

```text
编辑节点
```

表单字段：

```text
节点名称
节点类型
节点属性
备注
```

操作按钮：

```text
[保存修改]
[删除节点]
```

删除需要二次确认：

```text
删除节点会影响相关关系，是否确认？
```

---

## 11.4 原始图谱层：选中边

右侧上半部分显示关系详情。

下半部分显示编辑关系表单。

表单标题：

```text
编辑关系
```

表单字段：

```text
关系类型
起点节点
终点节点
关系说明
属性
```

操作按钮：

```text
[保存修改]
[删除关系]
```

删除需要二次确认：

```text
删除关系后将从原始图谱中移除，是否确认？
```

---

## 11.5 新增节点

点击：

```text
[新增节点]
```

打开表单。

字段：

```text
节点名称 *
节点类型 *
节点属性
备注
```

按钮：

```text
[取消] [新增]
```

校验：

```text
节点名称不能为空。
节点类型不能为空。
```

新增成功后：

```text
1. 图谱刷新或局部更新。
2. 新增节点被选中。
3. 右侧显示该节点详情。
```

---

## 11.6 新增关系

点击：

```text
[新增关系]
```

打开表单。

字段：

```text
起点节点 *
终点节点 *
关系类型 *
关系说明
属性
```

按钮：

```text
[取消] [新增]
```

校验：

```text
起点节点不能为空。
终点节点不能为空。
关系类型不能为空。
起点和终点不能完全无效。
```

新增成功后：

```text
1. 图谱刷新或局部更新。
2. 新增关系被选中。
3. 右侧显示该关系详情。
```

---

## 11.7 保存修改

保存修改规则：

```text
1. 点击保存后调用现有图谱干预接口。
2. 成功后更新右侧详情。
3. 成功后刷新图谱或局部更新。
4. 显示“保存成功”提示。
5. 保存失败时保留表单内容，不要清空。
```

---

## 11.8 删除节点

删除节点规则：

```text
1. 点击删除节点。
2. 弹出二次确认。
3. 确认后删除。
4. 删除成功后取消选中。
5. 刷新图谱。
```

二次确认文案：

```text
删除节点会影响相关关系，是否确认？
```

---

## 11.9 删除关系

删除关系规则：

```text
1. 点击删除关系。
2. 弹出二次确认。
3. 确认后删除。
4. 删除成功后取消选中。
5. 刷新图谱。
```

二次确认文案：

```text
删除关系后将从原始图谱中移除，是否确认？
```

# 21. 一句话总结

本阶段案件空间先做两件事：

```text
案件概览：
  让用户看清当前案件状态、证据列表和下一步。

案件证据地图：
  让用户清楚查看三类图谱，并只在原始图谱层维护节点和关系。
```

核心原则：

```text
案件概览负责“看状态和进入流程”。
案件证据地图负责“看结构和维护原始事实关系”。
智能分析和信息画像暂时不动。
```

证据地图页的分工必须明确：

```text
左侧栏：切换图谱类型。
顶部工具区：树形、力导、导出截图。
图谱区域：显示图谱和图谱图例。
右侧信息栏：显示选中节点/边详情，原始图谱层才显示编辑。
```
