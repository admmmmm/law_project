# Workspace 工作台前端设计说明
> 适用范围：本说明用于前端重设计的第一阶段，描述系统级「工作台 Workspace」的页面结构、左侧卡片交互、新建案件流程、检察技能库、知识库与设置页设计。
>
> 设计目标：把现有功能从“后台菜单集合”整理成“工作台 + 案件空间”的产品结构。工作台负责系统级操作，不绑定具体案件；案件空间负责围绕某一个案件展开办案分析。

---

## 1. 整体空间划分
前端整体分为两个空间：
```text
Workspace 工作台
Case Space 案件空间
```

### 1.1 Workspace 工作台
工作台是用户进入系统后的全局入口，用于处理不依赖某一个具体案件的操作。

工作台包含：
```text
我的案件
新建案件
检察技能库
知识库
设置
```

工作台解决的问题：
```text
我有哪些案件？
我要不要新建案件？
系统有哪些可复用技能？
系统有哪些法律和实务知识？
系统设置在哪里？
```

### 1.2 Case Space 案件空间
案件空间是用户选择某一个案件后进入的专属工作区。案件空间内的页面都围绕当前案件展开。

案件空间包含：
```text
案件概览
案件证据地图
智能分析
信息画像
```

案件空间解决的问题：
```text
当前案件处理到哪一步？
证据之间是什么关系？
能否基于证据做智能分析？
涉案人员关系和行为链条是什么？
分析结论能否溯源？
```

## 2. 工作台统一布局
工作台页面统一采用三块区域：
```text
左侧竖列卡片区
顶部工具区
右下主功能区
```

结构示意：
```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部工具区：页面标题 / 说明 / 搜索 / 主操作按钮                │
├───────────────┬──────────────────────────────────────────────┤
│ 左侧竖列卡片   │                                              │
│               │                                              │
│ 我的案件       │                                              │
│ 新建案件       │                 主功能区                     │
│ 检察技能库     │                                              │
│ 知识库         │                                              │
│ 设置           │                                              │
│               │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

### 2.1 左侧竖列卡片区
左侧竖列卡片是工作台的功能入口。

一级卡片：
```text
我的案件
新建案件
检察技能库
知识库
设置
```

有子功能的卡片，点击后展开子选项：
```text
检察技能库
  ├─ 浏览技能
  └─ 技能编辑

知识库
  ├─ 法律知识
  └─ 实务知识
```

### 2.2 左侧卡片交互规则
```text
1. 点击没有子选项的一级卡片，直接进入对应页面。
2. 点击有子选项的一级卡片，展开或收起子选项。
3. 点击子选项，进入具体页面。
4. 当前一级卡片高亮。
5. 当前子选项高亮。
6. 左侧栏支持折叠。
7. 展开状态显示图标 + 文字 + 简短说明。
8. 折叠状态只显示图标。
9. 折叠状态 hover 显示完整名称。
10. 不要让点击后无效的入口出现在左侧栏。
```

### 2.3 顶部工具区
顶部工具区用于展示当前页面的标题、说明和主要操作。
不同页面顶部内容不同，但结构统一：
```text
页面标题
页面说明
主操作按钮
搜索 / 筛选 / 辅助操作
```

示例：
```text
检察技能库 / 浏览技能

浏览和管理可复用的检察分析技能，用于指导智能分析、规则检查和画像生成。

[搜索技能] [标签筛选] [导入技能包]
```

### 2.4 主功能区
主功能区展示当前页面的核心业务内容。
设计原则：
```text
1. 一页只突出一个核心任务。
2. 主操作按钮最多一个。
3. 高级操作放到“更多”或“高级设置”里。
4. 技术调试信息不要默认显示。
5. 空状态要有明确引导。
```

# 4. 新建案件页面
## 4.1 页面定位
新建案件用于创建新的案件空间。
它不是一个简单表单，而是一个两步流程：
```text
第一步：填写案件信息
第二步：导入初始证据
```

完成后创建案件，并跳转进入新案件的案件空间。

建议路径：
```text
/cases/new
```

创建成功后跳转：
```text
/cases/:caseId
```

## 4.2 页面整体结构
左侧竖列卡片：
```text
我的案件
新建案件（当前高亮）
检察技能库
知识库
设置
```

顶部工具区：
```text
新建案件

创建案件并导入初始证据。系统将围绕该案件构建证据地图，并支持后续智能分析和信息画像。
```

主功能区：
```text
两步流程表单
```

底部固定操作区：
```text
[上一步 / 取消]                         [下一步 / 创建案件并进入]
```

底部按钮规则：
```text
1. 第一步左侧按钮为“取消”，右侧按钮为“下一步：导入证据”。
2. 第二步左侧按钮为“上一步”，右侧按钮为“创建案件并进入”。
3. 第二步允许用户不导入证据，直接创建空案件。
4. 创建成功后进入案件概览页。
```

## 4.3 步骤条设计
页面顶部或表单上方展示简洁步骤条：
```text
① 填写案件信息  →  ② 导入初始证据
```
当前步骤高亮，已完成步骤显示完成状态。

## 4.4 Step 1：填写案件信息
页面标题：
```text
第一步：填写案件信息
```

说明文字：
```text
请填写案件基础信息。后续证据导入、图谱构建、智能分析和信息画像都会围绕该案件展开。
```

字段设计：
```text
案件名称 *
案件类型 / 罪名模板
案号 / 内部编号
承办部门
承办人员
案件简要说明
```

必填字段：
```text
案件名称
```

可选字段：
```text
案件类型 / 罪名模板
案号 / 内部编号
承办部门
承办人员
案件简要说明
```

表单布局：
```text
┌──────────────────────────────────────────────┐
│ 基本信息                                      │
│                                              │
│ 案件名称 *        [                         ] │
│ 案号 / 内部编号    [                         ] │
│ 案件类型 / 罪名    [ 下拉选择                ] │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ 承办信息                                      │
│                                              │
│ 承办部门          [                         ] │
│ 承办人员          [                         ] │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ 案件说明                                      │
│                                              │
│ [ 多行文本框                                  ] │
│ [ 简要描述案件来源、背景、初步线索或说明         ] │
└──────────────────────────────────────────────┘
```

底部按钮：
```text
[取消]                                  [下一步：导入证据]
```

校验规则：
```text
1. 案件名称不能为空。
2. 案件名称过长时需要提示。
3. 案件类型可以为空，但建议提示“可后续补充”。
4. 点击下一步前进行基础校验。
```

## 4.5 Step 2：导入初始证据
页面标题：
```text
第二步：导入初始证据
```

说明文字：
```text
可以导入案卷材料、文书、笔录、资金流水、通联记录等证据。系统将对材料进行解析、分片，并用于后续证据地图和智能分析。
```

导入方式：
```text
上传文件
上传文件夹
上传压缩包
暂不导入，先创建案件
```

主功能区设计：
```text
┌──────────────────────┐
│ 上传文件               │
│ 适合少量单份材料         │
│                        │
│ [选择文件]              │
└──────────────────────┘

┌──────────────────────┐
│ 批量导入文件夹           │
│ 适合完整案卷材料         │
│                        │
│ [选择文件夹]            │
└──────────────────────┘

┌──────────────────────┐
│ 上传压缩包              │
│ 适合打包后的案卷材料      │
│                        │
│ [选择压缩包]            │
└──────────────────────┘
```

导入文件后显示：
```text
已选择文件数量
文件总大小
文件列表
上传状态
解析状态
失败文件提示
```

文件列表字段：
```text
文件名
文件类型
文件大小
状态
操作
```

状态包括：
```text
待上传
上传中
上传完成
解析中
解析完成
失败
```

底部按钮：
```text
[上一步]                             [创建案件并进入]
```

辅助按钮：
```text
[暂不导入，创建空案件]
```

交互规则：
```text
1. 用户可以上传文件后创建案件。
2. 用户也可以不上传文件，直接创建空案件。
3. 创建时如果有文件，则创建案件后执行导入。
4. 创建成功后跳转到 /cases/:caseId。
5. 如果导入过程较长，显示进度条。
6. 导入失败时，案件仍可创建，但需要提示失败文件。
```

## 4.6 新建案件空状态与错误状态
### 空状态
第二步没有选择文件时：
```text
尚未选择证据材料

你可以先创建空案件，稍后在案件空间中继续导入证据。
```
按钮：
```text
[暂不导入，创建空案件]
```

### 错误状态
创建失败时：
```text
案件创建失败，请检查网络连接或后端服务状态。
```

导入失败时：
```text
部分证据导入失败，案件已创建。你可以进入案件空间后重新导入失败材料。
```

# 5. 检察技能库
检察技能库用于管理可复用的检察分析技能。

左侧展开结构：
```text
检察技能库
  ├─ 浏览技能
  └─ 技能编辑
```

页面分为：
```text
浏览技能
技能详情
技能编辑
```

## 5.1 浏览技能页面
建议路径：
```text
/skills
```
或：
```text
/workspace/skills
```

页面定位：
```text
浏览系统内已有的检察分析技能包，查看技能用途、来源、标签，并进入详情页。
```

顶部工具区：
```text
检察技能库 / 浏览技能

浏览和管理可复用的检察分析技能，用于指导智能分析、规则检查和画像生成。

[搜索技能] [标签筛选] [导入技能包]
```

## 5.2 浏览技能页面结构
主功能区包括：
```text
搜索区
标签筛选区
技能卡片列表
```

结构示意：
```text
┌────────────────────────────────────────────────────┐
│ 搜索技能名称、简介、来源、适用场景                  │
└────────────────────────────────────────────────────┘

标签：
[全部] [证据审查] [文书完整性] [反侦查行为] [资金流风险]
[流程节点] [证据矛盾] [画像分析]

┌────────────────────────────────────────────────────┐
│ 技能名称                                             │

│ source：技能来源                                     │

│                                                     │
│ [查看详情] [编辑]                                    │
└────────────────────────────────────────────────────┘
```

## 5.3 搜索与筛选
搜索框 placeholder：
```text
搜索技能名称、简介、来源、适用场景
```

标签筛选建议：
```text
全部
证据审查
文书完整性
反侦查行为
资金流风险
流程节点
证据矛盾
画像分析
行为分析
补证建议
```

筛选规则：
```text
1. 搜索和标签筛选可以组合。
2. 没有结果时显示空状态。
3. 标签选中后高亮。
4. 支持清空筛选。
```

空状态：
```text
未找到匹配的技能

可以调整搜索关键词或清空标签筛选。
```
按钮：
```text
[清空筛选]
```

## 5.4 技能卡片设计
技能卡片必须展示以下字段：
```text
name
brief
source
```

建议额外展示：
```text
tags
version
updated_at
```

卡片示例：
```text
┌──────────────────────────────────────────────┐
│ 反侦查行为识别                                │
│                                              │
│ brief：检查案发后规避调查、串供、隐匿证据等行为线索 │
│ source：检察实务规则整理                       │
│                                              │
│ tags：行为异常 / 证据矛盾 / 侦查假设            │
│                                              │
│ [查看详情] [编辑]                              │
└──────────────────────────────────────────────┘
```

交互规则：
```text
1. 点击技能卡片主体，进入技能详情页。
2. 点击“查看详情”，进入技能详情页。
3. 点击“编辑”，进入技能编辑页，并加载该技能内容。
4. 从详情页可以返回浏览技能页。
5. 从编辑页可以保存后返回详情页。
```

检查重点

示例

页面结构：

## 5.6 技能编辑页面

## 5.7 技能编辑页面结构
技能编辑页以简洁文本编辑器为核心。
布局建议：
```text
左侧：技能元信息
中间：文本编辑器
右侧：预览 / 大纲 / 校验结果
```

结构示意：
```text
┌───────────────┬──────────────────────────────┬───────────────┐
│ 技能信息       │ 文本编辑器                    │ 预览 / 校验     │
│               │                              │               │
│ name          │ # 技能名称                     │ 大纲            │
│ brief         │ ## 适用场景                    │ 校验结果         │
│ source        │ ## 检查重点                    │ 保存状态         │
│ tags          │ ## 输出格式                    │               │
│               │ ## 示例                       │               │
└───────────────┴──────────────────────────────┴───────────────┘
```

## 5.8 技能编辑字段
左侧元信息字段：
```text
技能名称 name *
一句话简介 brief *
来源 source
标签 tags
版本 version
```

中间文本编辑器内容：
```text
# 技能名称

## 适用场景

## 分析目标

## 需要检查的材料

## 检查重点

## 输出格式

## 示例

## 注意事项
```

右侧预览 / 校验内容：
```text
Markdown 预览
标题大纲
必填项校验
保存状态
```

## 5.9 技能编辑器必要功能
技能编辑器需要具备：
```text
1. 文本编辑。
2. Markdown 预览。
3. 保存。
4. 取消 / 返回。
5. 新建技能。
6. 编辑已有技能。
7. 必填字段校验。
8. 未保存离开提示。
9. 标签编辑。
10. 简单格式模板插入。
```

可选功能：
```text
1. 导入本地 Markdown。
2. 导出技能。
3. 历史版本。
4. 测试运行。
```

第一阶段不强制做复杂编辑器，可以用 textarea + 预览实现。

## 5.10 技能编辑交互规则
```text
1. 从“浏览技能”点击技能卡片，进入详情页。
2. 从详情页点击“编辑技能”，进入编辑页。
3. 编辑页保存成功后，提示“保存成功”。
4. 保存后可以返回详情页。
5. 未保存时点击返回，需要二次确认。
6. 新建技能时，打开空编辑器。
7. 编辑已有技能时，加载原技能内容。
8. 保存失败时显示错误提示，不丢失编辑内容。
```

# 16. 工作台设计一句话总结
工作台负责系统级入口，核心是：
```text
我的案件 → 新建案件 → 检察技能库 → 知识库 → 设置
```

其中：
```text
我的案件：选择案件
新建案件：创建案件并导入初始证据
检察技能库：浏览和编辑可复用分析技能
知识库：维护法律知识和实务知识
设置：预留系统配置
```

设计重点不是“堆页面”，而是让用户一进系统就知道：
```text
我要先选择或创建案件；
案件之外的能力沉淀在技能库和知识库；
进入案件后，再围绕该案件做图谱、分析和画像。
```
