# 分析页三类疑点引擎计划

## 目标边界

分析页不再承担“事实画像”的主要展示。事实画像负责还原人物关系和行为经过；分析页负责在事实图谱之上生成疑点画像候选：

1. 跨案件碰撞：发现当前案件与其他案件共享的人、账户、地址、设备、机构、证据标签或相似关系结构。
2. 假设分析：由系统或检察官提出假设，再用图谱、passage 和三元组验证。
3. 可疑资金流动：先用图算法和 LLM 解释资金路径，后续在样本足够时接入 GNN。

输出结果不直接作为结论。每条疑点都标注支持证据、反向风险、缺口和建议，检察官可以采纳，进入画像页的“疑点画像”区域。

## 数据流

### 1. 图谱准备

每个案件先被抽取为统一图谱：

- 节点：人物、机构、账户、地址、设备、证据文档、事件节点。
- 边：请托、指派、转账、通话、同事、亲属、经营、批准、释放、调解等。
- 属性：时间点、时间段、金额、证据 ID、passage 来源、置信度。

跨案件分析不会重新抽取，而是读取已经入库的图谱。如果某个案件还没有图谱，先触发普通分析生成图谱。

### 2. 跨案件碰撞

系统从当前案件图中抽出可碰撞实体：

- 人名、别名、手机号、银行账户、机构、地址、设备、金额对象。
- 证据标签和高频关系类型。

然后与其他案件图做匹配：

- exact match：完全相同的人名、账号、手机号、机构名。
- weak match：同名不同证据、相似标签、同一地址片段、同一中间账户。
- pattern match：相同结构，如“请托 -> 中间人 -> 公职人员”“转账 -> 过桥账户 -> 控制账户”。

MVP 先做 exact/weak match，输出共享实体和共享关系。后续再做子图同构和嵌套关系合并。

### 3. 假设分析

假设不是“让 LLM 自己判案”，而是一个可以被图谱验证的对象：

```json
{
  "title": "王静可能通过何晓初向杨周武输送利益",
  "type": "request_chain",
  "claim": "王静与杨周武之间可能存在请托和利益输送链条",
  "expected_patterns": [
    "王静 -> 请托/联系 -> 何晓初",
    "何晓初 -> 联系/转交/收受 -> 杨周武",
    "杨周武 -> 指派/安排/释放/调解 -> 案件处置"
  ]
}
```

验证方法分三类：

- induction：从多个相似事实归纳模式，例如多次通话 + 多笔资金 + 后续释放。
- deduction：从法律要件模板推导需要哪些证据，例如徇私枉法需要身份、职权、枉法处置、主观明知/徇私动机、结果因果。
- abduction：从异常结果倒推最可能解释，例如“本应追诉却释放”可能由请托、利益输送、职权干预解释。

系统执行图操作：

- 多跳路径搜索：嫌疑人到请托人、中间人、资金节点、处置结果之间的路径。
- 时间约束：路径是否满足“先请托/资金，后处置”。
- 证据覆盖：每个关键边是否有证据 ID 或 passage 支撑。
- 反证检查：是否存在明显否定该假设的边或材料。

没有严重违反图谱的假设进入候选池，状态为 candidate / plausible / supported / conflicted。

### 4. 可疑资金流动

MVP 使用图算法：

- 多跳资金路径：2-5 跳资金从来源到接收方的路径。
- 中心性近似：出入度、金额汇总、是否连接多个关键人物。
- 回流/闭环：A -> B -> C -> A 或相似金额短期回流。
- 现金化：ATM 取现、柜台存款、现金存入与关键处置节点相邻。

LLM 负责把这些图算法结果解释成人能读懂的疑点，不负责凭空判断洗钱或犯罪成立。

后续 GNN 模式需要更多样本：

- 大量真实或高质量模拟交易网络。
- 标注过的异常路径、正常路径、过桥账户、现金化链条。
- 节点特征：账户类型、交易频率、金额分布、时间间隔、关系角色。
- 边特征：金额、时间、备注、渠道、方向、交易间隔。

在数据不足前，GNN 只写成未来增强，不作为当前系统结论来源。

## 交互修正

这三个功能不是自动全量扫描后吐候选，而是三个由检察官触发的分析动作。

### 跨案件碰撞

检察官先选择系统中某个或多个案件，系统把这些案件拉入“临时态案件”。临时态只用于本轮分析：

- 不改写原案件图谱。
- 不自动把同名节点合并为同一自然人。
- 输出“这些案件之间有什么共享实体、共享路径、相似结构，是否值得正式合并核查”。

后续如果检察官确认，可以再把相应子图正式并入。

### 假设验证

检察官输入自然语言假设，例如：

> 杨周武可能对某些执法文书做了篡改、倒签或补录。

系统执行多轮 RAG：

1. 根据假设生成多个检索问题。
2. 调用 HippoRAG/PPR 检索 evidence passage。
3. 收集相关图谱边和三元组。
4. 把 passage、三元组、检索问题一起交给 DeepSeek 写分析文本。

当前版本由后端模拟 tool-use 流程；后续可以升级成真正 function calling，让模型显式选择 search_graph / retrieve_passages / inspect_evidence。

### 可疑资金流

当前也先走 DeepSeek 多轮 RAG：

1. 检索资金流水、现金取存、过桥账户、关键人物之间资金往来。
2. 加入图谱中的资金边、通话边、处置节点。
3. DeepSeek 写成分析文本，说明已支持、疑点、缺口和下一步核查。

GNN 是后续增强，需要更多案件样本和标注资金网络，不作为当前结论来源。

## 页面形态

分析页只展示三块动作：

1. 跨案件碰撞
2. 假设验证
3. 可疑资金流

每条结果包含：

- 标题
- 方法：cross_case / hypothesis / financial_flow
- 风险等级
- 简短解释
- 支持图路径
- 支持证据
- 缺口
- 建议
- “采纳到疑点画像”按钮

画像页显示：

- 事实画像：人物关系、行为还原。
- 疑点画像：检察官采纳的疑点候选，明确标注“待核查/已采纳”，不与事实结论混淆。
